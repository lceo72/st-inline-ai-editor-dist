# AI 內文編輯器

供 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 使用的 [TavernHelper／JS-Slash-Runner](https://github.com/N0VI028/JS-Slash-Runner) 全域腳本。它會在每個使用者與 AI 樓層加一支魔杖，讓你用獨立的 Connection Profile 對反白文字或整個樓層下 AI 編修指令。

模型輸出不會直接覆蓋聊天。結果先進左右差異視窗，可以逐行挑要不要採用；接受只更新編輯器裡的草稿，最後仍要你明確按「儲存樓層」並再確認一次，才會寫回 SillyTavern。

目前版本：**0.8.0**

> 這個 repo 只放**發布產物**：可直接匯入的 JSON、腳本本體與變更說明。腳本內建的「檢查更新」讀的就是這裡的 `inline-ai-editor.js`。

## 執行需求

- SillyTavern 1.18.0 或更新版本，且已啟用內建的 Connection Manager。
- TavernHelper／JS-Slash-Runner **4.4.0 或更新版本**。世界書參考資料需要再新一點的版本；**一鍵更新需要 4.8.0 以上**（版本不夠時那個按鈕不會出現，其餘功能照常）。
- 至少一個可正常使用的 Connection Profile。

腳本只保存 Connection Profile 的 ID 與名稱，不讀取、複製或另存 API key。

## 安裝

1. 下載 [`酒館助手腳本-AI內文編輯器_0.8.0.json`](./酒館助手腳本-AI內文編輯器_0.8.0.json)。
2. 在 SillyTavern 打開 TavernHelper 的腳本庫，選「導入腳本」，匯入為全域腳本。
3. TavernHelper 通常會把新匯入的腳本設為停用，請手動啟用。
4. 重新載入目前聊天。
5. 點任一使用者或 AI 樓層動作列上的魔杖（在鉛筆左邊）。
6. 在編輯器右上角打開設定，選一個編輯器專用的 Connection Profile。

也可以自己新增一個 TavernHelper 全域腳本，再貼入 [`inline-ai-editor.js`](./inline-ai-editor.js) 的完整內容。

## 更新

**0.7.0 起**：打開設定最下面的「版本與更新」，按「更新腳本」。它換掉的是腳本庫裡這一支腳本的內容，不是新增第二份，**所以你的設定全部留著**——Connection Profile、編輯原則、客製指令與分組、世界書勾選、正則勾選都在。按完酒館助手會自己重新載入這支腳本，**連頁面都不用重整**；但編輯器會跟著關掉，所以裡面若有還沒儲存的草稿，先存好再更新。

**0.6.1 以前**（或酒館助手低於 4.8.0）：升級前先在舊版按「複製設定代碼」，匯入新版並啟用後按「匯入設定代碼」，然後停用或刪除舊的那一份。不同腳本實例的設定不共用，所以少了這一步新版會是空的。

⚠️ 按下「更新腳本」等於允許這個 repo 的擁有者在你的瀏覽器裡執行程式碼。抓下來的內容會先檢查長度、是不是這個專案的程式、讀不讀得到版號，但**沒有數位簽章可以驗證**。

不接受這個風險的話，什麼都不用關：**這個工具不會自己連外網**——沒有排程檢查、沒有啟動時檢查，只有你按下「檢查更新」或「更新腳本」的那一刻才會連線。改用手動匯入即可，所有其他功能都不受影響。

## 變更說明

0.8.0 的變更：

- **這次要帶什麼給 AI，全部搬到編輯器右邊的側邊欄了。** 參考樓層、世界書、正則規則各佔一區，可以各自展開收縮，側邊欄自己捲自己的，**不會再擠佔正文**。以前參考資料一展開就吃掉將近半個編輯器高度，選的樓層一多，能編字的地方只剩一小條。
- **勾了哪幾條世界書，現在一眼就看得到。** 挑條目還是在那個獨立視窗裡（沒變），但關掉之後，選中的條目就列在側邊欄上，點一列看整條內容，點 ✕ 取消一條，「全部取消」一次清空。0.7.x 編輯器上只有「已附加 5 條」一個數字，想確認是哪五條、想清掉，都得把視窗再開一次。
- **點參考樓層可以直接看那一樓的完整內文**，不用關掉編輯器跑回聊天裡找。若你勾的正則規則改動過那一樓，視窗會多一個「原始內容」分頁，可以對照規則到底做了什麼。
- **正則規則的勾選從設定視窗搬到側邊欄，而且勾了立刻生效**，不必再按「儲存設定」。勾一下，上面參考樓層的字元數當場就變。設定視窗裡那一區已經移除。
- **側邊欄最下面多了「預覽這次的請求」。** 按下去會顯示**完整的請求**——輸出協定、編輯原則、參考資料、包裹標記、目標樓層全部在內。指示的位置用佔位符代表（不論按哪個指令，它都落在同樣兩個位置）；上面兩顆按鈕切「局部修補／全文改寫」，因為這兩種模式的輸出協定完全不同。
- **編輯器視窗預設變寬**（980 → 1180），最小寬度提高到 780，好讓正文與側邊欄都有地方站。你以前拉過的尺寸若小於 820 會在開啟時被撐開一次，之後照常記住你自己拉的大小。
- **手機維持原本的樣子**：三區堆在正文上面、預設收合、最多佔半個畫面高度。
- 每一區的展開／收合狀態會記住。

0.7.2 的變更：

- **修正內建指令（重寫／縮短／擴寫／潤飾）那四列的排版跑掉。** 按鈕擠在名稱右邊、右半邊空一片。0.7.1 為了客製指令的拖曳握把把每一列改成四欄，但內建指令沒有握把（它們不能排序也不能分組），三個元素填進四欄就會錯位。此問題只在 0.7.1 出現過。

0.7.1 的變更：

- **修好「更多」選單被遮住。** 點開 ⋯ 之後選單幾乎整個被下面的內容蓋住——實測只露出 4px。原因是工具列為了在手機上能左右滑動而設了捲動屬性，這會讓瀏覽器把超出工具列的東西**裁掉**。選單改成不受工具列拘束的定位方式，並在你拖動編輯器視窗時自動收起。這個問題從 0.6.1 就存在。
- **分組現在看得出來了：每一組變成工具列上的一個資料夾按鈕。** 點「對白」就展開那一組的指令。0.7.0 把分組做成 ⋯ 選單裡的小標題，等於藏在兩層底下，工具列看起來跟沒分組一模一樣——那不算做到。**沒有分組的指令行為完全不變**（前三個釘在工具列、其餘收在 ⋯）。
- **分組改用下拉選單挑，不再是自由輸入。** 之前打錯一個字就會安靜地多出一個看起來一樣的組；現在只能從既有的組裡選，要開新的就選「＋ 建立新分組…」再打名字。
- **指令可以用拖曳排序，也可以拖到別組。** 設定裡每一列左邊多了一個握把，拖到別組的指令或組名上就換到那一組。手機上沒有拖曳（瀏覽器的拖放在觸控裝置不作用），仍然用箭頭與編輯視窗裡的「分組」。
- **「複製設定／貼上設定」改名為「複製設定代碼／匯入設定代碼」**，指令那組同理。原本的名字聽起來像是把某個指令複製一份，但它實際複製的是一段代碼文字。
- 修掉一個從 0.6.1 就有的小問題：客製指令只有三個以內時，桌機的「更多」按鈕會打開一個空選單（那三個已經釘在工具列上了）。現在桌機不顯示它，手機照常。

0.7.0 的變更：

- **修掉一個只有開發時看得到的問題：** 世界書條目的內部識別鍵原本用一個看不見的控制字元接「書名＋編號」，那讓整個程式檔在文字工具眼裡變成二進位檔——搜尋一個明明存在的東西會被回答「找不到」。改用 JSON 格式的鍵，一樣不會撞號。**你既有的世界書勾選不受影響**（設定裡存的是書名與編號兩個欄位，鍵是每次現算的）。
- **選世界書條目改成獨立視窗了。** 原本它擠在編輯器裡，自己還有一層捲軸，條目多了就要一直往下拉、字也擠在一起。現在按「選條目」跳出一個大視窗，搜尋框與書本選單固定在上面不會被捲走。勾好關掉就生效，沒有「確定／取消」——勾選當下就存好了。**在這個視窗裡按 Escape 關的是視窗，不是編輯器**，草稿與反白都留著。
- **編輯器上那一行改寫「已附加 N 條」，視窗裡寫「勾選中 N 條」。** 兩個數字算的本來就是不同的東西（真的會送出的 vs 你勾了幾條），過去兩處都寫「已選」，看起來像勾選自己跑掉了。
- **連續勾選變順了。** 以前每勾一下就把整份參考資料重算一次，連勾五條就重算五次；現在等你停手才算一次。勾選框、標籤與保存都仍然是立即的。
- **客製指令可以分組了。** 指令設定裡多一個「分組」欄位，打一個新名字就開一組。設定畫面與編輯器的 ⋯ 選單都會照組分段，上下移動限制在同一組內。舊的指令沒有分組，看起來跟以前完全一樣。
- **可以只複製客製指令。** 客製指令那一區多了「複製指令代碼／匯入指令代碼」，只帶指令與它們的分組，不含 Connection Profile、編輯原則與內建指令的修改。**貼上是「加進去」**——你現有的指令一條都不會被覆蓋，同名的兩條都留著。貼錯欄位（把整包設定貼進指令欄，或反過來）會被擋下來並告訴你該貼哪裡。
- **新增「檢查更新」與「更新腳本」。** 在設定最下面的「版本與更新」那一區。**這個工具不會自己去查有沒有新版**——只有你按下「檢查更新」的那一刻才連外網。

0.6.1 的變更：

- **魔杖從 ⋯ 選單裡拉出來了。** 現在直接顯示在樓層動作列上、鉛筆的左邊，不必先展開「訊息操作」才點得到。原本它跟翻譯、生圖那些放在同一個摺疊群組裡，等於這個工具的唯一入口要按兩次才到得了。

- **修正窄螢幕（手機）上「查看整個樓層的修改位置」排版錯亂。** 那一區原本會把原文與修改後**一行一行交錯**顯示，上面還頂著兩個標題卻沒有標到任何東西。現在跟主要的差異視窗一樣用頁籤切換，一次看一邊。此問題只在 0.6.0 出現過。
- 差異視窗的效能整理：詞級比對原本每一行左右各算一次相同的結果，現在算一次兩邊共用；「查看整個樓層的修改位置」原本每勾一次就把整個樓層重新比對一遍（**連摺疊起來看不見時也算**），現在只在展開時算。長樓層勾選會明顯順一些。
- 其餘為內部整理，功能未變。

0.6.0 的變更：

- **可以挑要接受哪幾處修改了。** 差異視窗每一個**有變更的行**左側多出一個 checkbox，**預設全部勾好**——你的工作是把不想要的取消掉，不是一項一項挑。取消某一行就保留那一行的原文。
- 版面沒有多一區：勾選框就在原有的左右對比裡，跟它管的那一行同一列。取消的行會淡掉，一眼看得出哪些沒採用。
- **局部修補與全文改寫都能用。** 因為選擇的單位是「差異的一行」，不是模型回傳的格式。
- 全部取消時「接受修改」會消失，因為沒有東西可以接受。
- 接受時寫進草稿的是**你當下勾選的結果**，不是模型提出的全部修改。兩段式儲存完全不變：接受仍然只更新草稿，寫回樓層仍然要第二次確認。
- 取消一行**新增**的內容時，那一行整行不加，不會留下一行空白；取消一行**刪除**時，原本那行會留著。
- ⚠️ **同一行裡的多處修改是一起決定的。** 如果模型在同一行內改了兩個地方，那一行只有一個勾選框，要就兩個都要。這是刻意的：修補只在一開始套用一次，之後勾選只在原文與結果之間選，所以不會出現「取消 A 卻讓 B 跟著失效」這種事。
- 差異視窗改成整列對齊的格線，順帶修掉長句在左右換行行數不同時、兩邊會逐漸對不齊的問題。
- **明確標出需要 TavernHelper 4.4.0 以上**。這不是新增限制，是本來就存在但沒寫出來的：寫回樓層用的 `refresh: 'affected'` 是 4.4.0 才有的。

0.5.1 的變更：

- **臨時指令會記住剛剛打的字了。** 同一個編輯器視窗裡再次打開「臨時指令」，指示欄會帶回上次送出的內容，不用重打一次；想改就直接在上面改。
- 只留在**這一次打開的編輯器**裡：關掉編輯器、或去開另一個樓層的編輯器，指示欄都是空的。這段文字不會寫進設定，也不會跟著「複製設定代碼」被備份。
- 只有**按下送出**的指示會被記住；按取消不會。

0.5.0 的變更：

- **參考資料會記住了。** 世界書勾選一律留到下次；參考樓層**只留在同一個聊天裡**，換到別的聊天會自動清空——因為第 42 樓在別的聊天是完全不同的一場戲，而摺疊那一行看起來會一模一樣。這兩項都跟著「複製設定代碼／匯入設定代碼」一起備份。
- **可以把世界書條目當參考資料了。** 編輯器的「參考資料」區裡多了一個「世界書」小節：展開後會列出這個聊天現在生效的世界書（全域啟用、角色卡綁定、聊天綁定），**逐條勾選**要附上去的設定。勾起來的內容跟參考樓層一樣是**唯讀背景**，永遠不會被寫回聊天，也不會動到你的世界書。
- **勾了就送**，不看那條在 SillyTavern 裡是不是啟用、關鍵字有沒有命中。所以你可以做一本平常不啟用、只給編輯器用的世界書（例如文風備忘、專有名詞表），在「其他世界書」那一組裡展開就找得到。
- **用下拉選單一次挑一本世界書**，只顯示那一本的條目，勾好再換下一本。找不到在哪一本時用搜尋，它會跨全部世界書找。已經勾起來的條目一律集中列在上方，點 ✕ 取消。
- **送出前看得到花多少**：折疊那一行直接寫「已選 N 條 · X 字元」，外層參考資料那一行會把樓層與世界書的字元數合起來算。
- **這個功能一行都不碰 SillyTavern 內部。** 原本規劃的做法是呼叫 SillyTavern 自己的世界書召回引擎（那樣關鍵字會自動命中），查證後放棄了：那個引擎就算用「唯讀模式」呼叫，仍然會清掉其他擴充排給**你下一次正常對話**的世界書條目，而且從腳本這邊補救不了。詳見 ADR-0004。
- 一條都沒勾時，送出的內容與 0.4.0 完全一致，既有用法不受影響。
- ⚠️ 需要較新的酒館助手（要有 `getWorldbook`）。版本太舊時，那一區會直接告訴你去更新，而不是給你一個永遠空白的清單。

0.4.0 的變更：

- **可以附加參考樓層了。** 編輯器多了一區「參考資料」：填上樓層編號（例如 `30, 42-46`），那些樓層就會以**唯讀背景**的身分附在請求裡。它們永遠不會被寫回聊天——這個工具編輯的仍然只有一個樓層，只是能看到更多背景。旁邊有「前 5 樓」「前 10 樓」快捷，按下去只是幫你把數字填進輸入框。關掉編輯器就清空。
- **送出前看得到花多少。** 折疊那一行直接寫出樓層範圍與字元數；展開後會逐樓列出角色與開頭幾十字，打錯號碼當場就看得出來。
- **可以挑選自己的正則規則套用在參考資料上。** 設定視窗最下方新增「參考資料的正則規則」，列出你所有的 SillyTavern 正則。**勾了就跑**——不看規則自帶的深度、來源、目的地，也不看它在 SillyTavern 裡是不是停用中。
- **差異視窗可以查看這次送出的完整請求**，包含協定、編輯原則、指示、參考資料與可編輯範圍。結果很怪時，這是用來分辨「資料帶錯」還是「指示寫爛」的。
- **區塊標記改用全形角括號**（`＜＜＜EDITABLE_SCOPE＞＞＞`）。這樣聊天內容裡若剛好出現半形的同名字串，模型也不會誤判區塊界線。**你的原文一個字都不會被改**——這點很重要，因為可編輯範圍要拿回來逐字比對再寫回樓層，動它會讓每一項修補都落空。`<search>` 與 `<replace>` 維持半形不變。
- 局部修補失敗、而且這次帶了參考資料時，警告會多一句提示往這個方向查。
- 沒填參考資料時，送出的內容與 0.3.0 一致（只有上述標記形態改變），既有指令的行為不受影響。
- **修正在某些環境下完全無法儲存樓層、而且編輯器關不掉的問題。** 原因是瀏覽器把原生的確認視窗直接忽略掉（腳本跑在 SillyTavern 的 iframe 裡，該 iframe 若被沙箱限制，`confirm()` 不會跳視窗、而是直接當作你按了「取消」）。所有確認視窗改由工具自己繪製，不再依賴瀏覽器願不願意跳原生對話框。**兩段式儲存完全不變**——接受 AI 修改仍然只更新草稿，寫回樓層仍然需要第二次確認。此問題自 0.1.0 起潛伏，是環境變化後才浮現。
- **匯入檔改成帶版號的檔名**（`酒館助手腳本-AI內文編輯器_0.4.0.json`）。每一版都會留在 repo 裡，不再被下一版覆蓋。

0.3.0 的變更：

- **四個內建指令（重寫、縮短、擴寫、潤飾）可以完整編輯了。** 欄位與客製指令相同：指示、編輯原則覆寫、Connection Profile、最大輸出 Tokens、編輯模式、名稱、圖示、顯示／隱藏。改壞了按「還原預設」。內建指令仍不可刪除，也不與客製指令混排序。編輯過的內建指令會被凍結，日後版本更新不再改動它。
- **新增設定備份**：「複製設定」與「貼上設定」，讓升級不必重打所有設定。貼上前會確認一次；貼到無法辨識的內容會整筆拒絕並說明原因，不會半套用。
- **介面用詞統一**，讓提示詞的三層可以分辨：「全域提示詞」改稱**全域編輯原則**、「系統提示詞覆寫」改稱**編輯原則覆寫**、指令表單裡的「指令」欄位改稱**指示**，內部協定統一稱**輸出協定**。只有顯示文字改變，設定資料未動。
- **修正編輯器視窗第一次儲存設定後不再置中**：視窗位置在設定正規化時會被重複處理，「沒有記錄位置」會變成「位置 0」，於是視窗永遠貼在左上角。此問題自 0.1.0 起存在。
